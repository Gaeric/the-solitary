# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this repo is

A **Slay the Spire 2 mod** ("The Solitary") built in **C# on Godot.NET SDK 4.5.1**. The mod patches the shipped game assembly (`sts2.dll`) at runtime using **HarmonyLib** and is loaded by the game's mod loader. The game runs on .NET 10 / C# 13.

## Repository layout (tracked content only)

- `Scripts/` — the mod's C# source. One entry point + one file per feature/patch.
- `TheSolitary.csproj` — build config; references the game's `sts2.dll` and `0Harmony.dll`.
- `TheSolitary.json` — mod manifest read by the game loader (`id`, `version`, `has_pck`, `has_dll`, `affects_gameplay`).
- `project.godot` / `export_presets.cfg` — Godot project + Windows export preset (packs a `.pck`).
- `localization/zhs/cards.json` — Chinese (zh-Hans) localization strings; keyed like `CARD_ID.title` / `CARD_ID.description`.
- `sts2_src/` — **gitignored**, read-only reference. This is the game's decompiled/recovered source (via `recover.sh` + `gdre_tools`), present only so you can read game types/signatures. **Never edit it; never import game source from here into the mod build.** Treat it as documentation.
- `.uid` files (e.g. `Entry.cs.uid`) — Godot resource IDs. Don't hand-edit; they're regenerated by the Godot editor.

## Build & deploy

The `.csproj` is **generated, not committed.** A tracked template (`TheSolitary.csproj.template`) holds `@STS2_DIR@` / `@STS2_DATA_DIR@` / `@GODOT_EXE@` placeholders. The Makefile generates `TheSolitary.csproj` (gitignored) from it on demand: if the file does not exist, the placeholders are substituted with the values from `config.mk`; if it already exists, it is left untouched. Delete `TheSolitary.csproj` to force regeneration after editing `config.mk`. Generating the file (rather than passing `-p:` on the `dotnet` command line) is required because the Godot.NET SDK spawns nested MSBuild invocations that re-read the `.csproj` and would ignore CLI property overrides.

**One-time setup:** copy `config.mk.example` to `config.mk` (gitignored) and fill in your local paths (use forward slashes on every OS — MSBuild accepts them):

- `STS2_DIR` — your `Slay the Spire 2` install dir.
- `STS2_DATA_DIR` — derived from `STS2_DIR` + host OS if omitted; must contain `sts2.dll` and `0Harmony.dll`.
- `GODOT_EXE` — path to a Godot 4.5.1 **mono** editor binary.

Build commands (run from repo root via `make`):

- `make build` — generate `TheSolitary.csproj` if missing, build the mod DLL, auto-deploy it + `TheSolitary.json` into `<Sts2Dir>/mods/TheSolitary/`. (`Copy Mod` MSBuild target does the deploy.)
- `make publish` — same generate/build cycle, then export the `.pck` via Godot headless (`ExportPck` target). `has_pck: true` in the manifest requires this.
- `make decomp` — recover game source into `sts2_src/` (requires `gdre_tools` on PATH).
- `make clean` / `make help` — clean artifacts / list targets.

There is **no test project / no lint config** in the tracked repo. `sts2_src/RiderTestRunner/` is game-internal, not part of this mod.

Restart the game to load a freshly built mod.

## Game type references

- Game code lives under the `MegaCrit.Sts2.*` namespaces (e.g. `MegaCrit.Sts2.Core.Entities.Cards`, `MegaCrit.Sts2.Core.Models`, `MegaCrit.Sts2.Core.Modding`). Browse these in `sts2_src/src/` to find exact signatures before patching.
- The mod's own namespace is `TheSolitary.Scripts`.
- Custom tscn-attached scripts must be registered via `ScriptManagerBridge.LookupScriptsInAssembly(typeof(Entry).Assembly)` in the initializer (see `Scripts/Entry.cs`).

## Modding conventions (from existing code)

- **Entry point**: a class annotated `[ModInitializer(nameof(Init))]` with a `public static void Init()`. Inside it:
  1. `new Harmony("sts2.<author>.<modid>").PatchAll();` — the Harmony ID string should be unique; don't collide with other mods.
  2. `ScriptManagerBridge.LookupScriptsInAssembly(...)` if you attach C# to `.tscn` scenes.
  3. `Log.Info(...)` for startup logging (`MegaCrit.Sts2.Core.Logging`).
- **Patches** use `[HarmonyPatch]` attributes. Follow the existing patterns in `Scripts/`:
  - `Postfix` with `__instance` to mutate after construction.
  - `Prefix` returning `false` to fully replace a method; set `ref <returnType> __result`.
  - To change a card's rarity, reflect the backing field: `typeof(CardModel).GetField("<Rarity>k__BackingField", BindingFlags.Instance | BindingFlags.NonPublic)` and `SetValue(instance, (CardRarity)N)`.
  - Dynamic values: `((CardModel)card).DynamicVars.<Name>.BaseValue = ...m;` (note the `m` decimal suffix).
  - Energy: `((CardModel)card).EnergyCost.UpgradeBy(-1)` / `AddThisCombat(-1)`.

## Code style

- C# 13, nullable enabled, `ImplicitUsings` on, `AllowUnsafeBlocks` on (per `.csproj`).
- Source comments and localization are Chinese (zh-Hans); match the surrounding language when editing comments.
- `.editorconfig` only sets UTF-8; `.gitattributes` forces LF line endings for text files — keep new files LF + UTF-8.
- Existing files use `var`, PascalCase for types/methods, camelCase/PascalCase params per Harmony convention (`__instance`, `__result`).

## Repo etiquette

- Single branch workflow on `master`; remote is `git@github.com:Gaeric/the-solitary.git`.
- Commit messages are short, lowercase, imperative (e.g. `update up_my_sleeve`, `auto publish`). No conventional-commit prefixes enforced.
- The `.csproj` is generated from `TheSolitary.csproj.template` (tracked) and gitignored; never commit `TheSolitary.csproj` itself. Local paths come from `config.mk` (gitignored) at generation time — delete the generated file and rebuild to pick up `config.mk` changes.

## Gotchas

- **`sts2_src/` is not part of the build.** It is recovered game source for reference only and is gitignored. If you need a game type's signature, read it there but do not add it to the project.
- **`min_game_version`** in `TheSolitary.json` (currently `0.105.0`) must stay compatible with the target game build; game updates can rename/move `MegaCrit.Sts2.*` members and break patches — re-verify against `sts2_src/` after game updates (re-run `recover.sh` to refresh it).
- The mod targets `net10.0`; ensure your SDK matches or the Godot build will fail.
- Manifest flags matter: `has_dll: true` expects the built DLL; `has_pck: true` expects `make publish` to have produced the `.pck`. Both land in the same `mods/TheSolitary/` folder.
